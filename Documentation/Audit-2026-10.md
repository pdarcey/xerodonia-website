## Fixed

1. **Heading levels skipped on `/apps/` and `/blog/`** (W3C error). Product and post cards always used `<h3>`. That's right on the home page, where they sit under an `<h2>`, but on the listing pages they follow the `<h1>` directly. Both partials now take a `cardHeading` variable (default `h3`), and those two pages set it to `h2`. The cards look the same.
2. **`aria-label` on `<pre>`** (W3C error, home page and `/apps/`). The obfuscate card's terminal example had `aria-label="Example command"`, which isn't allowed on a `<pre>`. I removed it, because the `$` prompt already makes clear it's a command.
3. **Screenshots downloaded at 800 px to show at about 160 px.** Every screenshot's `sizes` was `90vw`. Portrait screenshots, though, are sized by *height* in CSS, so a phone shot is only about 10rem wide on a phone. `screenshotSizes()` in `eleventy.config.js` now works out `sizes` from each image's shape, following the two `.shot-image--…` rules in `site.css`. This saves about 160 KiB on Blueprint's page. Displayed sizes don't change.

## Checked and fine

**SEO**
- Every page has `lang="en-AU"`, a canonical URL, a meta description, Open Graph and Twitter tags, and a skip link.
- No two pages share a `<title>`.
- `sitemap.xml` lists all 25 public pages. The 404 page is rightly left out.
- JSON-LD is valid on every page (the post-build guard checks this).
- `BreadcrumbList` is on the 13 pages that are at least two levels deep: the app pages, the app privacy and support pages, and the blog post. The consulting sub-pages use the Consulting sub-navigation instead.

**App Store Review Guidelines**
- **5.1.3 Health:** Blueprint's policy says health data is never sent off the device, never stored by Blueprint (in iCloud or anywhere else), never shared, and never used for advertising, marketing or data mining.
- **Contacts:** Blueprint and Upcoming Birthdays say contacts stay on the device.
- **Location:** Borderstamp says location is processed on the device, and only the places you earned stamps for are kept.
- **1.5 Support:** every App Store app's support page has an email link and an FAQ.
- **Pre-release:** no App Store links or badges anywhere. `appStoreUrl()` keeps them hidden until `status` is `app-store`.

**Apple trademarks and Australian items**
- The Apple trademark notice and the ABN are in the footer.
- Consulting prices say whether they include GST.
- The website's privacy policy discloses GitHub Pages' IP logging.

**External links**
The three redirects are all intended:
- the sitemap's XML namespace (`http://www.sitemaps.org/…`, a name, not a link to visit)
- `obfuscate.git` (a clone URL shown as code)
- GitHub's privacy statement (a redirect that only adds `/en/`)

The MCP endpoint answers a plain GET with **406**. That's expected, and it answers an MCP `tools/list` POST with 200.

## Not changed (noted)

- **Render-blocking stylesheet (about 155 ms in Lighthouse's estimate):** inlining the 25 KB stylesheet would stop browsers caching it between pages, and Performance is already 100. Leave as is.
- **Remaining 24–28 KiB of image savings:** the smallest generated screenshot width is 480 px, while a phone at 1.75× needs about 285 px. A 320 px size would close the gap, but it adds about 70 files. Not worth it yet.
- **Advice in Lighthouse's "insights" panel** (network dependency tree, render-blocking): this doesn't count towards any score.

## How the checks were run (CI in Stage 6b)

```bash
npm run build
# Internal links and anchors (offline). --index-files is needed, or links like /privacy/#apps fail.
lychee --offline --include-fragments --root-dir "$PWD/_site" --index-files index.html '_site/**/*.html' '_site/*.xml' '_site/*.txt'
# External links
grep -rhoE 'https?://[^" <>)]+' _site | grep -v '://xerodonia\.com' | sort -u | lychee -
# Lighthouse
CHROME_PATH="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" npx lhci collect --staticDistDir=_site --url=http://localhost/index.html …
```

W3C validation used the online Nu checker (`https://validator.w3.org/nu/?out=json`), because this Mac has no Java. CI will run `vnu-jar` instead.

## Gotchas for 6b

- lychee needs **`--index-files index.html`** with `--include-fragments`. Without it, `/privacy/#apps` is reported as a missing fragment, even though `id="apps"` exists.
- The external-link run should **exclude the sitemap namespace and `*.git`**, and **accept 406 from the MCP endpoint**.
- `npm install` holds back `fsevents`' install script. That's harmless, because it's an optional Mac file watcher.
